# Day 5 — Sprint Review, Postman Demo & Retrospective

### Week 6 · Phase 3, Sprint 1

---

## What I Did

- Demoed the full Sprint 1 API live via Postman: paginated/filtered/sorted
  patient browsing, and the Critical-reading auto-follow-up business rule
  end-to-end (see `Postman-Demo-Script.md`).
- Audited every Sprint 1 backlog task against the program's Definition of Done
  (correct status codes, PR reviewed, happy + error path tested, no unhandled
  exceptions) — all items passed; nothing carries over incomplete.
- Tracked test-suite growth across the sprint as a concrete velocity signal
  (10 → 13 → 19 → 24 tests), documented in `Sprint1-Summary.md`.
- Logged two real bugs found and fixed during the sprint, and identified three
  concrete Sprint 2 backlog items.
- Wrote a specific, actionable retrospective (`Sprint1-Retrospective.md`) —
  one concrete process change for Sprint 2, not a vague "be more careful."

## Files in This Folder

- `Postman-Demo-Script.md` — the exact demo sequence used
- `Sprint1-Summary.md` — velocity metrics, Definition of Done audit, bugs found, Sprint 2 backlog

## Key Takeaway

A retrospective that only lists what went well skips the useful half — the
constructor-change/test-update gap identified here is what makes Sprint 2's
planning measurably more accurate than Sprint 1's, not just another week of the
same process.
